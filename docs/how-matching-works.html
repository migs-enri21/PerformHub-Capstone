How organizers find performers

Click the numbers or Next. One example person: Kai.

1. Three fields, not tags

There is no free-text tag box. The system only understands these:

Category = role
Admin list. Same ID on event and performer.
SingerDancerHost
Specialty = skill
Fixed list in code. Can pick more than one.
BassElectric Guitar
Genre = style
Fixed list in code. Can pick more than one.
R&BOther

2. Performer fills profile

Kai does not type tags. Kai picks from the lists on Edit Profile.

Categories (every role they do)

SingerDancerHost

Specialty dropdown — open and pick more than one

BassElectric Guitar

Genre dropdown — open and pick more than one

R&BOther

3. Organizer searches

Find Performers. Empty filter = skip that field. Filled filter = must match.

Example filter:

Category: Singer Specialty: Bass Genre: R&B Date: Sep 20

The system checks each filled box, then requires all of them (AND).

4. Does Kai match?

SHOW Kai

Singer → Kai has Singer

Bass → inside [Bass, Electric Guitar]

R&B → inside [R&B, Other]

Also works: Guitar, Other, or Dancer.

HIDE Kai

Host → Kai did not check Host

Classical → not in Kai’s genres

Violin → not in Kai’s specialties

Or Sep 20 is booked / day-off / Google busy.

Rule: organizer filters = AND. Kai’s lists = OR.

5. Suggested vs search

Find Performers
Uses category + specialty + genre + date.
Suggested performers
Uses event categories ∩ performer categories only. Genre is ignored here.

Performer Home recommended events = the reverse: open events that share a category ID.

6. Who is hidden anyway

Even a perfect match is hidden unless all of these are true:

Active account · onboarding done · admin verified · verified badge

If a date is set: no pending/accepted/completed booking that day, not day-off, not Google-busy.
